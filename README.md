
# QR Event Pass System

An end-to-end QR code system for managing event access, attendee verification, and redemption-based workflows at college events.
---

## How It Works

```
Google Form → Google Sheets → SQLite DB → QR Generation → Email → Scan at Event → Logged to Sheet
```

1. Attendees register via Google Form and the data is logged into Google Sheet
2. `sync_sheet.py` pulls their data into a local SQLite database
3. `generate_qr.py` creates a branded QR PNG for each attendee
4. `send_email.py` emails each person their personal QR pass
5. At the event, an admin opens opens the `index.html` file being served via nginx... and points their phone camera at QR codes
6. `app.py` validates each scan and logs successful redemptions to a separate Google Sheet

## Running Order

### Step 1 — Sync registrations from Google Sheets

```bash
python3 sync_sheet.py
```

Reads emails and names from the Form responses sheet and inserts new users into SQLite. Safe to re-run — existing users are skipped.

### Step 2 — Generate QR codes

```bash
python3 generate_qr.py
```

Creates a branded PNG QR code for every user in the database. Output goes to `qrcodes/`. Re-running only generates missing files.

### Step 3 — Send QR codes by email

```bash
python3 send_email.py

```

Emails each user their QR pass. If the script execution is interrupted, it's resumed at the point of interruption when re-run.

### Step 4 — Start the backend API

```bash
python3 app.py
```

Keep this running throughout the event.

For production, use gunicorn. It offers better performance and reliability:

```bash
gunicorn -w 1 -b 0.0.0.0:5000 app:app
```
> **Note:** This project has currently only been tested with a single Gunicorn worker. Multiple workers may work, but have not been tested yet.

### Step 5 — Scan at the event

`index.html` is served via nginx... Open the site as set in nginx config and scan the QR codes

## Database Schema:

```sql
CREATE TABLE users (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    email       TEXT    NOT NULL UNIQUE,
    name        TEXT,
    token       TEXT    NOT NULL UNIQUE,
    email_sent  INTEGER NOT NULL DEFAULT 0,
    redeemed    INTEGER NOT NULL DEFAULT 0,
    redeemed_at TEXT
);
```

## Output Sheet (Redemption Log)

Every successful scan appends a row to the configured Google Sheet:

| email | name | redeemed_at | scanner_email | token |
|---|---|---|---|---|
| a@example.com | Test Subject | 2026-08-08 11:11:11 IST | admin@gmail.com | uuid... |

---

## Features

- QR codes encode **only the UUID tokens that are generated by the script** — no email or personal data is exposed
- Only emails listed in `SCANNER_EMAILS` can call `/scan` or `/export` via the backend API endpoint!
- Each token can only be redeemed once <-> Might add an option to change this in the future

## Built With

- [Flask](https://flask.palletsprojects.com/) — backend API
- [qrcode](https://github.com/lincolnloop/python-qrcode) — QR generation
- [Pillow](https://python-pillow.org/) — logo embedding

### The browser's native `BarcodeDetector` API is used by default for QR code detection. `jsQR` is included as a fallback for browsers that do not support `BarcodeDetector API`
